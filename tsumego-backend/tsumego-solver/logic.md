囲碁の死活(詰碁)をminimax法により解析するプログラムを作成します。

入力:
SGFフォーマットで初期盤面が与えられます。
例: (;GM[1]FF[4]CA[UTF-8]SZ[19]RU[Chinese]KM[7.5]AW[qc][qd][re][qb][sd][pb]AB[pc][pd][qe][qf][ob][nc][rf][sf])
- ただし、簡単のため黒先白死の問題とします。将来的には黒先コウ、黒先生き、など結論が異なる問題も入力として用意する可能性があります。

出力:
初期盤面から、黒はその後白がどんな手を尽くしても白を死形にできる手だけを手順に組み込み、白はその後黒が手抜きできない手(黒が1度パスをすると、その後どんな手順を尽くしても白を生かしてしまう手)のすべてを手順に組み込みます。
回答例: (;GM[1]FF[4]CA[UTF-8]SZ[19]RU[Chinese]KM[7.5]AW[qc][qd][re][qb][sd][pb]AB[pc][pd][qe][qf][ob][nc][rf][sf];B[rd](;W[rc];B[sb](;W[pa];B[ra];W[se];B[sc])(;W[rb];B[se];W[pa];B[ra])(;W[ra];B[pa];W[se];B[sc])(;W[se];B[sc])(;W[sc];B[se];W[pa];B[ra]))(;W[sb];B[rc];W[rb];B[se])(;W[rb];B[se]))
- 黒番と白番で着手のポリシーが異なります。
  - 黒番は最善手を追求します。すなわち、白がどのような手を打っても白を殺せる手だけを探索します。(この手は局面に対して一意ではなく、複数ある可能性もあります)
  - 白番は相手が手抜けるかどうかのみ考えます。相手(黒番)が現局面からパスできない手のすべてを探索します。

言語指定: C++ (g++ Rev14, Build by MSYS2 project) 15.2.0
外部ライブラリの利用可

アルゴリズム:
再帰によって探索します。
局面とは、石の配置(その配置になった手順が違っても同一視する)のみを表す言葉とする。
局面Aと手番turn, 着点P, 初期局面からAまでの手順tree(分岐のない木), に対して、関数シグネチャ: minimax-search(A, turn, P, tree)は、[結果(白死、白生、コウのいずれか), SubTree(着点P以降の正解手順の木構造)] を返す。着点PにはPassも許容する。
また、探索を効率化するためのメモとして、[局面のハッシュ値, 手番]をキーとして、値[結果, SubTree]をとるハッシュメモを利用する。

minimax-searchの第一戻り値(結果)は、局面Aで手番turnのプレイヤーが着点Pに着手すると、白の死が確定するときに白死を返し、白の生きが確定するときに白生を返す。
minimax-searchの第二戻り値(SubTree)は、
  - turnが黒番の場合、第一戻り値が白死なら、(turn, P)から始めて、ゲーム木の末端までのすべての探索済み手順の木を返す。

minimax-search(A, turn, P, tree) のフローは以下である。!turnでturnの次の手番を表し、next(A, turn, P)で局面Aからturnの手番がPに着手した局面を表す。

1. 局面next(A, turn, P)と手番!turn がここまでのminimax-searchですでに探索済みの局面か判定する。探索済みであればメモ化した結果とSubTreeを返却して終了。未探索の局面であれば2.に進む。

2. 局面next(A, turn, P)が生形のリストに含まれているか判定する。含まれている場合、 メモにキー[hash(next(A, turn, P)), !turn]値に[白生, Null]を返して終了する。
  - 生形のリストは `../data/alive/` 以下に、 `alive0001.sgf` などのファイル名でSGF形式で与えられる。
  - 生形をつくる碁石は可能な限り碁盤の右上に配置される。
    - 生形の例(SGF): `(;GM[1]FF[4]CA[UTF-8]SZ[19]RU[Chinese]KM[7.5]AW[pb][qb][rb][sb][ob][oa])`
  - 判定方法: (以下は静的なデータに対する処理なので、`../data/alive/` 以下のファイルに変更がある場合のみリスト生成を行い、差分が無い場合は各生形に対するメタデータなどに保存しておいた内部点のリストを参照すれば十分である)
    - 囲碁のルール上、生形の外側がどのようになっていても構わないため、生形の内部が一致するかどうかで判定を行う。
    - 生形ごとに内部点を作成: 返却用のリストとして空のlistを用意し、碁盤を左から右に走るループ yoko in (0,18) に対して、
      - yoko 列の座標に石が一つもなければlistを空にして continue (注意: 飛び地となっている石は無視できる)
      - yoko列の座標に石がある場合は、石がある座標の最大値 tate_max として、(yoko, tate_max) をlistに追加する
      - ループを抜けた後の list は list[i].first の列に対して区間 [0, list[i].second]が生形の内部を表す区間となる。
    - この内部の点のみによって、生形と局面(A, turn, P)が一致しているかどうかを判定する。一致していればnext(A, turn,P)は生形と判定し、どの生形とも一致していなければ生形と判定せず次のステップへ

3. 局面next(A, turn, P)が死形のリストに含まれているか判定する。判定法は参照するデータが `../data/dead/` 以下にあること以外はStep2.と同様に行う。
- 含まれている場合メモにキー[hash(next(A,turn,P)), !turn], 値[白死, SubTree] を追加し、[白死、SubTree]を返却して終了する。
- SubTreeは、
  - turnが黒番で、かつtreeにpassが含まれていない場合のみ、next(A, turn, P)のみを末端ノードに持つ木とする。
  - それ以外の場合は空の木とする。

4. treeにPassが含まれておらず、かつ !turn が黒番なら、minimax-search(next(A, turn, P), !turn , Pass, tree + Pass) を実行し、白死が返却された場合は、hashメモリストに キー[hash(next(A,turn,P)), !turn] 値[白死, Null] を追加し、[白死, Null]を返却して終了する。

5. 局面next(A, turn, P) から !turn が着手可能な着点のリストLを生成する。ただし、着点のリストは盤面全体から選ぶのではなく、石が置かれた内部の点から、囲碁のルール上打つことができる点をリスト化すれば十分である。内部の点リストは、Step2.での内部点生成と同様に行う。Step2.では静的なデータに対して内部点を生成したのに対し、本ステップでは局面next(A,turn,P)に対して動的に内部の点を生成することに注意。
  - 例えば、入力で与えた例では、初期局面から候補手となりうる着点は[oa][pa][qa][ra][sa][rb][sb][rc][sc][rd][se]の11点のみであり、これが初期局面, 手番黒での着手可能な着点のリストLとなる。

6. l \in L についてのループで、minimax-search(next(A, turn, P), !turn, l, tree + l) を実行する。
  - !turn が黒番のとき、
     - [白死, SubTree] が返却された場合
       - treeにpassが含まれていない場合は、ハッシュメモリストにキー[hash(next(A, turn, P)), !turn,] 値[白死, l + SubTree] を追加する。
       - treeにpassが含まれている場合は、ハッシュメモリストにキー[hash(next(A,turn,P)), !turn] 値[白死, Null]を追加する
     - 全てのlについて 白生 が返却された場合、 ハッシュメモリストにキー[hash(next(A,turn,P)), !turn] 値[白生, Null] を追加し、[白生, Null]を返却して終了する。
     - 一つ以上の白死が見つかっていれば、[白死, merge\_{l\in L, 白死が返却されたl}(l + SubTree_l)]を返却して終了する。
       - 黒番ではすべての正解手順を発見したいので、一つ目の白死でループをブレイクせずに、l \in L について全探索することに注意。
  - !turnが白番のとき、
     - 全てのlについて 白死 が返却された場合、ハッシュメモリストにキー[hash(next(A,turn,P)), !turn] 値[白死, merge\_{l\in L, SubTree_lがNullでない}(l + SubTree_l)]を追加し、[白死, merge\_{l\in L, SubTree_lがNullでない}(l + SubTree_l)] を返却して終了する
     - 一つでも 白生 が見つかった場合、ループをブレイクし、ハッシュメモリストにキー[hash(next(A,turn,P)), !turn] 値[白生, Null] を追加し、[白生, Null]を返却して終了する。


以上が minimax-searchのフローです。このロジックが正しいかを検証してください。
